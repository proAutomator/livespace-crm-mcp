**Goal:** Fix two defects found by real MCP-client testing after M4: (1) retried reads reuse a spent Livespace session and fail with a MISLEADING `AUTH_FAILED (561)` - every retry must sign a fresh attempt; (2) `detail: "minimal"` returns the full record shape with blanked values instead of omitting fields.

**Architecture:** Restructure `src/livespace/client.ts` so the retry loop wraps the WHOLE composite attempt (token fetch -> signature -> signed POST) via a `prepare()` callback over a single-attempt HTTP primitive. Retryability is marked AT THE SOURCE (only the HTTP primitive mints retryable errors), never inferred from error codes. `projectRecord` switches from blank-fill to key OMISSION with the type ripple handled in all three consumer tools. No new dependencies, no new env vars.

## Live evidence (2026-08-06, isolated on the sandbox)

1. **The 561 bug (reproduced 3 ways on the same 162-deal window fetch, ~2 MB):**
   default client (timeout 15 s, retries on): first call OK in 13.8 s, second
   call `AUTH_FAILED (561)`; timeout 60 s: three of three OK (17-19 s);
   retries off: honest `TIMEOUT` every time. Mechanism: `call()` mints
   `_api_sha`/`_api_session` ONCE and `post()` retries the same signed body;
   the server consumed the session on the timed-out first attempt, so the
   replay is rejected as 561 and the model is told to check its credentials.
   This poisons EVERY signed-call retry (5xx too), not only timeouts - the
   M2.5 retry tests passed only because fake fetches do not validate
   sessions.
2. **Latency/size reality:** a deal serializes at ~13 KB. `Deal/getAll`
   limit 5 -> ~1.2 s; limit 50 -> ~6 s; limit 200 (162 rows, 1.97 MB) ->
   14-19 s. The token call itself is sub-second. The default 15 s timeout
   sits BELOW an honest SORT_WINDOW fetch.
3. **Minimal detail waste:** 5 deals at `detail: "minimal"` = 2555 bytes,
   28 keys per item, only 7 non-empty; `standard` = 4168 bytes. Blanked
   fields also collide with the server's own instruction that empty values
   mean "not filled in".

## Global Constraints

- All M0b-M4 constraints apply (English, TDD, synthetic fixtures, offline unit tests, `{code, message, hint}` errors, counts-only text channel, no new deps/env vars, never push).
- **Retryability is a property of the TRANSPORT, marked at the source.** Only `singleFetch` constructs retryable errors (HTTP 429, HTTP >= 500, TimeoutError, network throw). Errors built by `errorFromEnvelope` or any shape validation are NEVER retried, regardless of their `code` - envelope results 400/500/516/520 also map to code `UPSTREAM_ERROR`, so a code-based classifier would wrongly retry token-endpoint business failures. The marker is a `readonly transport: boolean` field on `LivespaceError` (default false; set only by `singleFetch`).
- **Write semantics, phase-aware (matches today exactly):** the token fetch is a safe read even inside a write - PREPARE-phase transport failures retry up to `maxAttempts` for writes too. The moment the SIGNED POST has been dispatched (`signedDispatch: true`), a write stops unconditionally: HTTP >= 500 / timeout / network throw on that dispatch -> `WRITE_OUTCOME_UNKNOWN`; **HTTP 429 on the dispatch stays `RATE_LIMITED` with outcome KNOWN** (rejected before processing - the existing test "write rejected by 429 maps to RATE_LIMITED" at tests/livespace/client.test.ts must stay green).
- Cancellation semantics preserved: signal-state checks, `cancelledError()`, abort never retried.
- Jitter/backoff/Retry-After preserved (capped full jitter, `random` injectable); `Retry-After` now rides on the error as `retryAfterMs`.
- **Timeouts:** client default `timeoutMs` 15_000 -> 30_000. Per-call `LivespaceCallOptions.timeoutMs` override applies ONLY to the signed dispatch; the token fetch always uses `TOKEN_TIMEOUT_MS = 10_000` (measured sub-second; keeps the worst case per slot at ~3 x (10 + 60) s instead of 3 x 120 s - record this arithmetic in a code comment).
- `singleFetch` invariants (from the current inline loop - MUST hold): `combineSignals(AbortSignal.timeout(timeoutMs), signal)` with `dispose()` ONLY in `finally`; `await response.json()` INSIDE the try (body read inside the timed window); the TIMEOUT message reports the EFFECTIVE timeout used, not the client default.
- Empty-value semantics: WITHIN a requested detail level, empty strings/nulls still mean "not filled in" and are returned; fields OUTSIDE the level are ABSENT. Whitelist key sets are unchanged from M4.

```ts
// errors.ts - two optional readonly fields appended (all existing positional
// call sites stay valid):
export class LivespaceError extends Error {
  constructor(code, message, hint, resultCode?,
    readonly retryAfterMs?: number,
    readonly transport: boolean = false) {...}
}

// client.ts
export interface LivespaceClientOptions {
  fetchImpl?; timeoutMs?: number;  // DEFAULT CHANGES: 15_000 -> 30_000
  maxAttempts?; sleep?; random?;
}
export interface LivespaceCallOptions {
  signal?: AbortSignal; write?: boolean;
  timeoutMs?: number;   // NEW: signed-dispatch-only override
}
```

Internal design (exact):

1. `singleFetch(url, body, opts: { timeoutMs, signal }): Promise<Envelope>` -
   ONE HTTP attempt honoring the invariants above. Classification (all with
   `transport: true`): caller-aborted -> `cancelledError()` (not transport);
   HTTP 429 -> `RATE_LIMITED` + `retryAfterMs`; HTTP >= 500 ->
   `UPSTREAM_ERROR` + `retryAfterMs`; TimeoutError -> `TIMEOUT` (message
   uses the effective timeoutMs); other throw -> `NETWORK_ERROR`. Else parse
   and return the envelope.
2. `getToken(signal): Promise<{token, sessionId}>` - one `singleFetch` with
   `TOKEN_TIMEOUT_MS` + today's envelope/shape validation (business failures
   via `errorFromEnvelope`/AUTH_FAILED are non-transport -> never retried).
3. `post(prepare: () => Promise<{url, body}>, opts: {write, signal, timeoutMs?})`
   - the retry engine. Per attempt: signal-state check; `phase = "prepare"`;
   `const req = await prepare()`; `phase = "dispatch"`;
   `singleFetch(req.url, req.body, { timeoutMs: opts.timeoutMs ?? this.timeoutMs, signal })`.
   Catch: rethrow immediately when NOT `error.transport` or when the caller
   signal aborted. Write + dispatch-phase: HTTP >= 500/timeout/network ->
   `WRITE_OUTCOME_UNKNOWN` (carry resultCode); 429 -> rethrow `RATE_LIMITED`
   as-is. Reads (and write prepare-phase failures) retry with
   `retryDelayMs(attempt, error.retryAfterMs)` up to `maxAttempts`, then
   rethrow the last error.
4. `call()` - unchanged surface; `prepare` closes over module/method/params:
   `getToken` -> `buildSignature` -> body. Every attempt gets a fresh
   `_api_session`/`_api_sha`. Envelope business validation stays in `call`
   after `post` returns. One throttle slot per logical call (unchanged).
5. `records.ts`: `const LARGE_PAGE_TIMEOUT_MS = 60_000;` (comment cites the
   measured 14-19 s / 200-row window); list fetchers pass
   `timeoutMs: LARGE_PAGE_TIMEOUT_MS` to `client.call` when `limit >= 100`.
   `listTasks` (fixed 50-row pages, ~6 s) keeps defaults.
