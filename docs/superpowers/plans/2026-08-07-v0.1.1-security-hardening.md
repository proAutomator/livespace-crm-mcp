# v0.1.1 Security Hardening and Release Plan

**Goal:** Ship the two post-release denial-of-service fixes and close the
remaining high-value safety gaps for local MCP users without expanding the
tool surface or changing Livespace write semantics.

## Security contract

- A missing setting starts the server read-only. Writes require an explicit
  `LIVESPACE_MCP_ENABLE_WRITES=true` opt-in.
- `LIVESPACE_MCP_READ_ONLY=true` remains an emergency kill switch and wins
  over the write opt-in.
- Write-enabled startup requires a random `MCP_AUTH_TOKEN` and
  `MCP_REQUEST_STATE_KEY`, including on loopback.
- A client without form elicitation cannot execute a write unless the operator
  explicitly enables the unsafe compatibility mode. Preview remains available.
- Admission plus body upload keeps its existing 10 second deadline. Tool
  execution gets a separate bounded signal so an authenticated caller cannot
  hold every active slot indefinitely. Streamed tool responses keep their
  admission slot until completion, cancellation or the execution deadline.
- MCP responses are not cacheable. The unauthenticated liveness endpoint
  returns status only.
- No token, CRM payload, personal data or real credential enters source,
  tests, logs, release metadata or documentation.

## Task 1: Encode safe startup defaults

**Files:** `tests/config/server-env.test.ts`, `src/config/server-env.ts`,
`.env.example`, `server.json`.

1. Add failing tests for read-only default, explicit write opt-in, kill-switch
   precedence, strict boolean parsing, and write-enabled startup without auth.
2. Add `LIVESPACE_MCP_ENABLE_WRITES` and
   `MCP_ALLOW_UNBOUND_WRITE_CONFIRMATION` as strict booleans defaulting false.
3. Keep `LIVESPACE_MCP_READ_ONLY` as a strict emergency override.
4. Require auth and the existing stable request-state key whenever writes are
   enabled.
5. Publish only the safe write opt-in in Registry metadata, default false.

## Task 2: Close the unbound confirmation path

**Files:** `tests/server/write-support.test.ts`, write-tool contract tests,
`src/server/tools/write-support.ts`, `src/server/mcp.ts`, and the five write
tool modules.

1. Add a failing decision-table row proving `confirm: true` remains a preview
   without elicitation and without the compatibility opt-in.
2. Pass one process-level compatibility flag through write registration.
3. Preserve the signed, single-use elicitation path unchanged.
4. Preserve preview behavior on clients without elicitation.
5. Add a positive control proving the explicit compatibility opt-in retains
   the v0.1.0 behavior.

## Task 3: Bound execution and harden HTTP responses

**Files:** `tests/config/server-env.test.ts`, `tests/server/http.test.ts`,
`src/config/server-env.ts`, `src/server/app.ts`, `.env.example`.

1. Add a bounded `MCP_REQUEST_EXECUTION_TIMEOUT_MS` setting with a 90 second
   default and a 300 second hard maximum.
2. Start the execution deadline only after admission and body upload. Forward
   its abort signal through the SDK into tool work.
3. Keep the admission slot until the response body completes, is cancelled or
   reaches that deadline.
4. Preserve write `unknown_outcome` handling by aborting the real tool signal
   instead of replacing a tool response with a generic retryable error.
5. Set `Cache-Control: no-store` and `Vary: Authorization` on `/mcp`.
6. Return only `{ "status": "ok" }` from unauthenticated `/health`.

## Task 4: Document the operator controls

**Files:** `README.md`, `SECURITY.md`, `docs/security.md`,
`src/server/instructions.ts`, `tests/readme.test.ts`, relevant instruction and
release metadata tests.

1. Document read-only by default, the authenticated write opt-in, and the
   disabled-by-default compatibility path.
2. Recommend a dedicated least-privilege Livespace API user and separate test
   account.
3. Explain that CRM text is untrusted and that the MCP host or model can retain
   data or be influenced by prompt injection.
4. Add an incident runbook: stop the server, revoke the Livespace key, rotate
   both MCP secrets, restart, and review CRM write history.
5. Tell reverse-proxy operators not to cache or log MCP request and response
   bodies.
6. Bump every version-bearing artifact and public link to `0.1.1`.

## Task 5: Verify the release candidate

2. `bun run test:security`.
3. `bun test`.
4. `bun run typecheck`.

## Task 6: Publish and lock down the release path

1. Commit and push the verified release candidate to `main` using the existing
   maintainer identity and no generated attribution.
2. Require pull requests and the `test`, `gitleaks`, and `conformance` checks
   for administrators as well as other contributors. Disable routine bypass.
3. Add a protected npm release environment and a GitHub OIDC publish workflow
   with `contents: read`, `id-token: write`, and npm provenance.
4. Protect `v*` tags against update and deletion.
5. Publish npm `0.1.1`, create immutable tag and GitHub Release `v0.1.1`, then
   publish Registry metadata for `0.1.1`.
6. Verify the public npm integrity and provenance, release commit, Registry
   resolution, clean installation and CI status.

## Execution notes

Implemented test-first on 2026-08-07. The initial focused run failed on all
new safety assertions, including the streamed-response admission regression.
The final implementation:

- starts read-only unless writes are explicitly enabled and refuses a
  write-enabled process without independent authentication and confirmation
  secrets;
- refuses unbound `confirm: true` by default while preserving signed form
  elicitation and an operator-only compatibility escape hatch;
- gives post-upload execution its own deadline, holds admission through the
  response lifetime, and aborts tool work on timeout or response cancellation;
- sends non-cacheable MCP responses and exposes status only on `/health`;
- documents least privilege, untrusted CRM content, host retention, proxy
  handling and credential incident response;
- pins conformance in the lockfile and adds a least-privilege OIDC npm publish
  workflow for the protected `npm-release` environment;
- stops the sandbox smoke script from printing the connected user's identity.
